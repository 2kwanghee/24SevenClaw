## 목표
`scripts/auto_dev_pipeline.sh`의 STEP C를 Codex QA 호출(및 실패 시 위조 REVIEW.md 폴백)에서, 구현과 별도의 `claude -p` 세션으로 실행하는 읽기전용 리뷰어로 교체하여 "구현 에이전트 ≠ 리뷰 에이전트" 불변식을 강제한다.

## 가정 (Assumptions)
- `PIPELINE_MODEL_REVIEW` 기본값은 `claude-sonnet-5`(CE-367 패턴: 별칭 금지, 정식 모델명만) — 명시 근거(수용 기준 2항).
- 리뷰 입력 diff의 base는 기존 STEP C 위치에서 이미 확정된 분기(`WS_DELIVERY` 여부에 따른 `CUST_BASE` / `main`)를 그대로 재사용한다 — 구현 스텝(STEP B)이 이미 이 분기로 diff를 만들고 있으므로(`auto_dev_pipeline.sh:1057-1061` TASK.md 생성부) 동일 컨벤션 유지가 가장 보수적.
- 리뷰어 세션에는 `--dangerously-skip-permissions`를 주지 않고, 파일 수정 도구(Edit/Write) 자체를 프롬프트/툴 제한으로 배제한다. Claude CLI에 세밀한 tool allowlist 옵션이 없다면 `--disallowedTools`(또는 등가 CLI 플래그)로 Edit/Write/NotebookEdit을 명시 차단한다 — 실재 여부는 구현 단계에서 `claude -p --help` 확인 필요(신규 조사 항목, 없으면 프롬프트 상단 강제 지시로 대체하되 그 사실을 로그에 남긴다).
- 재시도는 "리뷰어 프로세스가 비정상 종료(exit≠0)"한 경우에만 1회, 리뷰 판정이 "실패"로 나온 경우는 정상 완료이므로 재시도 대상이 아니다(기존 실패 처리 경로로 넘김) — 티켓 4항의 "실행 불능"과 "판정 실패"를 구분.
- `.ralph/REVIEW.md` 소비처(`scripts/linear_reporter.py` 등)가 있으면 포맷 호환을 위해 기존 3값 판정 섹션 헤더를 최대한 유지한다 — 확인 필요 시 구현 단계에서 `grep -rn "REVIEW.md" scripts/ | grep -v auto_dev_pipeline` 로 소비처 존재 여부 재확인(현재 조사 결과 소비처 없음, 재확인 필요).

## 대상 파일
- `scripts/run_codex_review.sh` — **삭제**. Codex 호출·폴백 로직 전부 여기 있음.
- `scripts/auto_dev_pipeline.sh:1074-1086` (STEP C 블록) — Codex 호출부를 신규 리뷰 함수 호출로 교체. `resolve_impl_workdir`/`safe_git`/`impl_git`/`CUST_BASE`/`WS_DELIVERY`/`CLAUDE_LOG`/`record_metric`/`METRIC_RUN_ID` 등 기존 헬퍼·변수 재사용(신규 발명 금지).
- `scripts/auto_dev_pipeline.sh` 상단 env 선언부(44-45행 부근, `PIPELINE_MODEL_REFINE`/`PIPELINE_MODEL_IMPL` 옆) — `PIPELINE_MODEL_REVIEW="${PIPELINE_MODEL_REVIEW:-claude-sonnet-5}"` 추가.
- `templates/harness-core/PROMPT.review.md` — **신규**. `templates/harness-core/PROMPT.workspace.md`의 상단 "무인 실행이다 — 되묻기는 그 자체가 실패다" 절을 동일하게 배치하고, 리뷰 전용 지시(읽기전용·판정 3값·심각도/확신도 포함 전체 발견 보고)를 이어 붙인다.
- `.claude/agents/harness-worker.md` — 구현/리뷰 역할 분리 서술이 있다면 Codex 언급을 Claude 리뷰어로 갱신(범위: 해당 파일 내 Codex 관련 서술만, 재작성 금지).
- 문서(`docs/pipeline-guide.md` Step 5.5 부근 QA 스텝 서술) — Codex 언급 부분만 `/docs-sync` 절차로 사후 동기화(이 스펙의 구현 완료 후 별도 훅이 감지·표시하므로 이번 구현 스텝에는 미포함, 커밋 전 1회 `/docs-sync` 실행은 필수 관행 유지).

## 구현 단계
1. `scripts/auto_dev_pipeline.sh`에 `PIPELINE_MODEL_REVIEW` env 기본값 선언 추가(기존 `PIPELINE_MODEL_IMPL` 패턴과 동일 위치·형식).
2. `templates/harness-core/PROMPT.review.md` 작성: 상단에 `PROMPT.workspace.md`와 동일한 무인 선언(되묻기 금지) 절, 이어서 "너는 읽기전용 코드 리뷰어다. 파일을 수정하지 마라" 역할 정의, 입력으로 (a) diff 텍스트, (b) 인라인 구현 스펙(`.ralph/refined/<ISSUE>.md` 내용 또는 STEP A 산출물), (c) 수용 기준을 프롬프트에 인라인 삽입할 자리표시자를 둔다. 출력 포맷은 통과/실패/판정불가 3값 + 발견 사항 전부(심각도·확신도 포함)로 고정.
3. `scripts/auto_dev_pipeline.sh`에 신규 함수(예: `run_claude_review`)를 STEP C 자리(현 1074-1086행)에 정의/호출하는 형태로 작성:
   - diff 계산: `WS_DELIVERY=true`면 `impl_git diff --name-only "$CUST_BASE"` 계열(기존 TASK.md 생성부와 동일 분기), 아니면 `safe_git diff main`.
   - `PROMPT.review.md`를 읽어 diff·구현 스펙(`REFINED_FILE` 변수 재사용)·수용 기준을 치환해 리뷰 프롬프트 조립.
   - `claude -p "$REVIEW_PROMPT" --model "$PIPELINE_MODEL_REVIEW" --output-format stream-json --verbose` 실행(파일 수정 툴 비활성 옵션 포함, `--dangerously-skip-permissions` 미부여로 쓰기 작업 시 승인 프롬프트가 막히게 하거나 CLI가 지원하는 read-only 플래그 사용). 출력은 별도 로그 파일(예: `.ralph/review.stream.jsonl`)로 캡처.
   - `CLAUDE_LOG`(구현 세션 로그, 928-940행 패턴)와 동일한 방식으로 리뷰 로그에서도 `subtype:init` 이벤트를 파싱해 `session_id`(및 `model`)를 추출한다. 구현 세션의 `session_id`도 동일 패턴으로 추출해 두 값을 `log`로 비교 출력(예: `log "구현 세션=<impl_sid> 리뷰 세션=<review_sid> (분리 확인)"`) — 동일값이면 WARN 후 딜리버리 실패 처리(자기리뷰 재발 방지).
   - 리뷰 프로세스 exit code가 0이 아니면(비정상 종료) 1회 재시도, 재실패 시 기존 실패 처리 경로(`handle_task_failure` 등 STEP B에서 쓰는 것과 동일 함수) 호출 — 기본 REVIEW.md를 생성하지 않는다.
   - 정상 종료 시 리뷰어의 최종 텍스트 출력(stream-json의 마지막 assistant 메시지 또는 result 이벤트)을 `.ralph/REVIEW.md`로 저장.
   - `git status`를 리뷰 실행 전/후로 비교해 차이가 있으면 WARN 로그(리뷰어가 파일을 건드렸다는 뜻 — 수용 기준 3항 검증용 관측이지 별도 승인 게이트 신설 아님).
   - `record_metric "$METRIC_RUN_ID" "qa_done" ...` 호출은 유지하되 payload에 `"reviewer": "claude"`, `"review_session_id"`, `"impl_session_id"` 필드 추가.
4. `FLOWOPS_CODEX_REVIEW` 토글명은 의미가 바뀌었으므로 그대로 두되(SKIP 분기 포함, 회귀 최소화) 로그 문구만 "Claude 리뷰"로 갱신. 토글 자체의 이름 변경은 범위 밖(YAGNI — 요청에 토글 리네이밍 지시 없음).
5. `scripts/run_codex_review.sh` 삭제, 레포 내 이 스크립트에 대한 참조(예: 다른 스크립트/문서의 호출부) 재검색 후 함께 제거.
6. self-repo 경로와 워크스페이스 딜리버리 경로 양쪽에서 STEP C가 동일 함수를 타는지 확인(현재 코드 구조상 STEP C는 분기 없이 공통 실행되므로 별도 분기 신설 불필요 — diff 계산만 `WS_DELIVERY` 값으로 갈린다).

## 테스트
- 이 레포의 테스트 방식(쉘 스크립트 대상 bats/shell 테스트 존재 여부를 `tests/` 또는 `scripts/*test*` 탐색으로 먼저 확인 — 발견 시 해당 프레임워크로 작성).
- 최소 검증 항목:
  1. `run_claude_review` 관련 함수에 대해 diff 계산 분기(self-repo/workspace)가 각각 올바른 base를 사용하는지 단위 테스트.
  2. init 이벤트 파싱으로 `session_id` 추출 로직이 stream-json 샘플 라인에서 올바르게 값을 뽑는지(구현 세션 모델 검증 로직과 동일 패턴이므로 동일 테스트 구조 재사용).
  3. 리뷰 프로세스 exit≠0 → 1회 재시도 → 재실패 시 실패 경로로 빠지는 흐름(모킹된 `claude` 커맨드로 exit code 강제).
  4. `.ralph/REVIEW.md`가 리뷰 성공시에만 생성되고, 실패시 위조 파일이 남지 않는지.
- 커버리지 목표 ≥70%는 이 변경이 닿는 함수 범위 기준(전체 스크립트 아님).

## 준수할 컨벤션
- 커밋 메시지: `[root] CE-390 ...` 형식, 한국어.
- 브랜치: `ralph/CE-390`(이미 현재 브랜치로 존재 — 그대로 사용).
- CE-367 패턴: 모델은 정식 이름만(`claude-sonnet-5`), 별칭 사용 금지 + 실행 후 `subtype:init`으로 실제 모델 검증 로그 남기기(구현 세션과 동일 패턴을 리뷰 세션에도 적용).
- 기존 헬퍼(`safe_git`, `impl_git`, `resolve_impl_workdir`, `record_metric`, `is_enabled`) 재사용, 신규 유틸 함수 난립 금지.

## 도메인 제약 (Domain Constraints)
- **정합성 규칙**: 구현 세션과 리뷰 세션은 서로 다른 프로세스여야 하며, 동일 `session_id`가 관측되면 리뷰 불변식 위반으로 간주해 실패 처리한다(자기검증 금지 원칙, 사용자 확정 방침).
- **금지 사항**: 리뷰어 세션에는 파일 수정 권한(Edit/Write류 툴)을 부여하지 않는다. 리뷰어가 코드를 수정하면 그 자체로 구현/리뷰 분리 불변식 위반.
- **금지 사항**: 리뷰 실행 불능(비정상 종료) 시 위조된/기본 REVIEW.md를 생성해 성공으로 위장하지 않는다 — 실측 사고(SIP-1)의 재발 방지가 이 티켓의 존재 이유.
