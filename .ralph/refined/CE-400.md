## 목표
DB(`user_anthropic_credentials`, `credential_type=oauth_token`)에 등록된 구독 시트를 러너 로컬 원장(`.ralph/seats.json`)으로 자동 동기화하여, `llm_usage_ledger.seat_id`가 NULL로 떨어지는 근본 원인(로컬 seat_id가 비-UUID라 `_uuid_or_none`에 걸러짐)을 해소한다.

## 가정 (Assumptions)
- **seat_id 형식 충돌 해소**: `usage_ingest.py`의 `_uuid_or_none`(scripts/usage_ingest.py:55)은 `CLICKEYE_SEAT_ID`가 유효 UUID 문자열이 아니면 조용히 None으로 버린다. `apply_seat_env`(scripts/auto_dev_pipeline.sh:226)는 `CLICKEYE_SEAT_ID=$SEAT_ID`를 그대로 노출하고, `$SEAT_ID`는 `seat_map.py`의 ledger seat 엔트리 키(`--id`) 값이다. 따라서 **DB 동기화 시트의 ledger `seat_id` 키 자체를 `user_anthropic_credentials.id`의 전체 UUID 문자열로 등록**한다(`db-<uuid8>`처럼 축약하지 않음) — 이래야 `CLICKEYE_SEAT_ID`가 `_uuid_or_none` 검증을 통과해 ledger에 실제로 기록된다. 토큰 **파일명**만 `db-<uuid8>.token`처럼 8자 축약을 써도 무방(가독성 목적, seat_id 값과는 별개). 근거: 티켓 3항 "NULL 귀속 해소"는 `CLICKEYE_SEAT_ID`가 실제로 UUID여야만 달성 가능 — 가장 보수적 선택으로 seat_id=전체 UUID를 택함.
- **API 인증 패턴**: `GET /api/v1/ops/seat-quota/*`(clickeye-api/app/api/v1/seat_quota.py)와 동일하게 `verify_governance_token`(X-Governance-Token 헤더, governance.py:53) 의존성만 사용하고 RBAC은 요구하지 않는다. 신규 엔드포인트는 `ops_seats.py`로 분리한다(seat_quota.py와 관심사가 다름 — 잔량 스냅샷 vs 프로비저닝).
- **"active" 정의**: `seat_status == 'active'`인 `credential_type='oauth_token'` 행만 반환한다. exhausted/blocked는 응답에서 제외하되, 이미 로컬에 등재된 시트가 DB에서 blocked로 바뀐 경우를 로컬이 감지하려면 **상태 변경분도 함께 내려줘야 하므로**, 응답은 "active 시트 전체 + 최근 상태변경(active가 아닌) 시트 목록"의 두 세트로 구성한다고 가정(단순화: 응답에 seat_status 필드를 포함시켜 스크립트가 active/그 외를 분기 처리 — 별도 "최근 변경" 조회 API는 만들지 않는다, YAGNI).
- **감사 로그**: 호출 주체가 사람이 아니라 러너 프로세스이므로 "누가"는 특정 user가 아니라 "governance 토큰 보유 클라이언트"로 기록한다(구조화 로그 1줄: 반환 시트 수 + timestamp, 토큰/평문 미포함).
- **auth 저장 형식**: `seat_map.py`의 `auth` 딕셔너리는 `oauth_token_file` 또는 `config_dir` 중 하나만 갖는다는 기존 불변식을 유지 — DB 동기화 시트는 항상 `oauth_token_file`을 쓴다(config_dir 경로는 로컬 수동 시트 전용으로 남긴다).
- **로컬 수동 시트(seat-a/b) 보존**: `seat_map.py`의 `register_seat`는 이미 순수 함수이고 seat_id별로 독립 등재되므로, DB 동기화 대상 seat_id(전체 UUID 문자열)와 수동 seat_id("seat-a" 등)가 이름 공간에서 절대 충돌하지 않는다(수동 seat_id는 `SEAT_ID_RE`를 만족하는 짧은 별칭 관례). 별도 격리 로직 불필요.
- **디스패처 훅 실패 처리**: 스크립트 자체 종료 코드와 무관하게 호출부(`runner_dispatcher.sh` 등)는 항상 무시하고 계속 진행(비차단) — `seat_map.py resolve`와 동일한 "항상 exit 0" 철학은 적용하지 않되(동기화 실패를 알아야 하므로 stderr 경고 + 종료코드 자체는 남김), 호출부에서 `|| true`로 흡수한다.

## 구현 단계
1. `SeatProvisionItem`/`SeatProvisionResponse` 스키마 추가 (schemas/seat.py) — 토큰 필드는 이 스키마에서만 평문 노출(SeatTokenResponse와 동일 원칙).
2. `SeatService.list_all_for_provision()` 구현 — `select(UserAnthropicCredentials, User.email).join(User).where(credential_type='oauth_token')`, 각 행 `decrypt()`, 로그 1줄 남기고 `(seat, email, token)` 튜플 목록 반환.
3. `ops_seats.py` 라우터 작성, `router.py`에 등록. `verify_governance_token`을 governance.py에서 그대로 import(재정의 금지).
4. `seat_sync.py` 작성 — `sys.path`에 repo root를 추가해 `scripts.seat_map` 함수를 import(순수 함수 재사용, 중복 구현 금지). API_URL/GOVERNANCE_SERVICE_TOKEN env는 `usage_ingest.py`/`with_seat.sh`와 동일한 이름 재사용. 실패(네트워크/4xx/5xx)는 stderr 경고 후 `sys.exit(1)`(호출부가 `|| true`로 흡수), 부분 실패(개별 시트 파일 쓰기 실패)는 해당 시트만 skip하고 나머지는 계속.
5. 토큰 파일 쓰기는 `seat_map.write_ledger`와 동일한 원자적 패턴(tmp+os.replace) 재사용/모방, `os.chmod(tmp_path, 0o600)`를 rename 전에 적용.
6. 디스패처(또는 파이프라인) 진입점에 seat_sync 1회 호출 삽입 — 정확한 위치는 구현자가 `runner_dispatcher.sh`의 스폰 루프 진입 직전 지점을 확인 후 결정(현재 컨텍스트에서 정확한 라인 미확인 — 구현 시 재확인 필요).
7. openapi.json 재생성 + contracts 레포 generated 파일 동기화.

## 도메인 제약 (Domain Constraints)
- **데이터 민감도**: `user_anthropic_credentials.encrypted_api_key`(Fernet 암호화된 OAuth 토큰)는 복호화된 평문이 API 응답 바디(SeatTokenResponse/SeatProvisionResponse 전용) 밖으로 나가서는 안 되며, 어떤 로그·커밋 메시지·PR 코멘트에도 등장해서는 안 된다(기존 seat_service.py 주석 명시 불변식).
- **금지 사항**: 사용자당 시트 1개 유니크 제약(`UniqueConstraint(user_id, credential_type)`, ToS 방어)을 완화하는 어떤 변경도 금지 — 이 티켓 범위 밖.
- **정합성 규칙**: `CLICKEYE_SEAT_ID`로 노출되는 값은 반드시 유효 UUID 문자열이어야 `llm_usage_ledger.seat_id` 축에 귀속된다(`_uuid_or_none` 검증). 로컬 원장 seat_id 키의 명명 규칙을 바꿀 때는 이 제약을 항상 우선한다.
