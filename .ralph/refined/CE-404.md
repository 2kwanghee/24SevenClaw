## 목표
대시보드 "파이프라인 성공률" 위젯(`clickeye-web/src/app/(dashboard)/dashboard/page.tsx`)을 기간 선택(7/14/30일) + recharts PieChart + 최근 3일 일자별 성공/실패 추이로 확장한다. 백엔드 `days`/`trend_days` 파라미터와 `daily_outcomes`는 이미 제공되므로 프론트 전용 작업이다.

## 가정 (Assumptions)
- **기본 기간은 7일**(현행 유지) — 명세에 "기본 7일" 명시됨.
- **추이 기간은 고정 3일** — 명세가 "최근 3일 추이"로 고정 지정. 백엔드 `trend_days`는 최대 14까지 받지만 이 위젯에서는 항상 `trend_days=3`으로 호출한다(기간 프리셋과 별개 파라미터).
- **성공/실패 색상**: 기존 도넛이 성공=`var(--accent)`, 범례 실패=`red-500`(하드코딩)을 섞어 쓰던 상태를 정리해 **성공=`var(--accent)`, 실패=`var(--chart-danger)`**로 파이·추이 차트 모두 통일한다. 신규 CSS 변수는 추가하지 않는다(이미 CE-403에서 도입된 `--chart-danger` 재사용, YAGNI).
- **API 클라이언트 파라미터 확장**: `clickeye-web/src/lib/api-client.ts`의 `observability.getSummary`는 현재 인자를 받지 않고 `ObservabilitySummaryResponse` 타입에 `daily_outcomes` 필드가 누락돼 있음 — 둘 다 이 티켓 범위에서 보정이 필요하다(요청사항 달성의 필수 전제이므로 "금지범위(백엔드)" 위반이 아니라 프론트 타입/클라이언트 계약 정합).
- **쿼리 키**: `useObservabilitySummary`는 `days`를 인자로 받아 `queryKey`에 포함시켜 기간 변경 시 캐시 분리 + 재조회되게 한다(다른 훅들의 `params` 포함 패턴과 동일).
- **i18n**: 기존 관례상 `ja`/`id`에는 `observability.dashboard` 네임스페이스 자체가 없으므로(선행 사실), 이 티켓도 `ko`/`en`만 갱신한다.
- **빈 데이터 정의**: `successCount === 0 && failureCount === 0`(기존 로직 유지) — 이 경우 파이 대신 안내 문구, 추이 바는 0값 막대(축 슬롯은 백엔드가 항상 3일치 채움)로 표시.

## 구현 단계
1. `api-client.ts`: `ObservabilityDailyOutcome` 인터페이스 추가, `ObservabilitySummaryResponse.daily_outcomes` 필드 추가, `getSummary`에 `days` 쿼리 파라미터 지원 추가(기존 `buildQuery` 유틸 재사용)
2. `use-observability.ts`: `useObservabilitySummary(days)` 시그니처 변경, queryKey에 `days` 반영
3. `ko.json`/`en.json`: 기간/추이 관련 키 추가 및 기존 하드코딩 문자열 파라미터화
4. `dashboard/page.tsx`:
   a. 기간 상태(`days`) 추가 + `BentoCard action` 슬롯에 프리셋 선택 UI 구현
   b. `SuccessRateDonut`를 recharts `Pie`/`PieChart` 기반으로 재작성(중앙 % 라벨은 절대배치 오버레이 유지)
   c. `DailyOutcomeTrend` 컴포넌트 신규 작성, `data.daily_outcomes` 소비, 파이 옆/아래 배치
   d. 빈 데이터·다크모드·반응형 처리(기존 `var(--*)` 토큰만 사용, 신규 색상 하드코딩 금지)
5. `pnpm lint` / `pnpm typecheck` / `pnpm build` 실행해 통과 확인

- API 호출은 `lib/api-client.ts`의 자동생성 클라이언트 경유(직접 fetch 금지), 서버 데이터는 TanStack Query에만 저장(Zustand 금지) — 루트/web CLAUDE.md

- `any` 타입 사용 금지, Props는 `{ComponentName}Props` 인터페이스로 정의
