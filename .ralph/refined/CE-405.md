## 목표

대시보드에 `BentoCard` 2개(계정 잔량 시각화, 계정 사용순위 리스트 1차)를 추가한다. 백엔드 무변경, 기존 `GET /observability/seats` 응답(`SeatObservabilityResponse`)만 사용한다.

## 가정 (Assumptions)

- **"최근 사용일" 컬럼은 생략한다.** `SeatObservabilityEntry`에는 계정 단위 최근 사용 시각 필드가 없다. `SeatQuotaLatestEntry.usage_fetched_at`은 window(5h/7d/scoped) 스냅샷 조회 시각이라 "계정이 마지막으로 사용된 날"과 의미가 다르고, `ProjectSummaryResponse.last_activity_at`은 프로젝트 단위(계정 단위 아님)라 사용할 수 없다. CE-402 `usage` 피벗(`UsagePivotResponse`)도 `group_by`가 `project_id/seat_id/model/request_kind`뿐이라 날짜축이 없다. 태스크 지침("잘못된 의미 노출 금지")에 따라 가장 보수적으로 컬럼을 생략한다.
- **잔량(7d %) 컬럼값**: `SeatObservabilityEntry.windows`에서 `window === "7d"` 항목의 `pct`(string)를 사용한다. `scope_name`이 있는(모델별 scoped) 항목은 이 리스트에서는 제외하고 게이지 위젯에서만 다룬다(리스트는 "1차" 범위로 계정 단위 요약만).
- **24h 소비 정렬 기준**: `usage_24h_input_tokens + usage_24h_output_tokens` 합산 내림차순. 태스크가 "24h 소비 토큰"이라 단일 값을 요구하므로 input+output 합산을 표시값·정렬키로 겸용한다.
- **게이지/래디얼 바**: 프로젝트에 기존 RadialBarChart 실사용 예시가 없다(현재 대시보드 도넛은 conic-gradient 수제 구현). recharts 패키지에는 `RadialBarChart`가 이미 존재하므로 신규 의존성 추가 없이 `RadialBarChart`+`RadialBar`를 사용한다(추측성 라이브러리 도입 아님, 기존 의존성 재사용).
- **소진 예측 배지**: `SeatQuotaLatestEntry.projected_exhaustion_at`(및 `will_last_to_reset`)로 "리셋 전 소진 위험" 여부만 배지로 표시한다. 없는 경우(null) 배지 생략.
- **클릭 라우팅**: `BentoCard`의 `href` prop(기존 `project-card.tsx` 패턴)으로 `/observability/seats`로 이동시킨다. `onClick`이 아닌 `href` 방식을 택한 이유는 카드 전체가 Link가 되어 별도 상태 관리가 필요 없기 때문.
- **테스트**: 이 프로젝트에는 대시보드/시트 위젯 전용 테스트가 없다(전체에 `__tests__` 4개, 딜리버리 쪽뿐). "테스트 방식 준수"를 위해 최소 1개(빈 상태 렌더 + 정렬 로직) Vitest+RTL 테스트를 신설 컴포넌트 옆 `__tests__/`에 추가한다.
- **i18n 네임스페이스**: 기존 `observability.dashboard`(ko.json L1153-1186 부근) 아래 새 키 그룹(`seatBalance`, `seatRanking`)을 추가한다. `observability.seats`(시트 상세 페이지)의 기존 키(`empty`, `noWindows` 등)는 재사용하지 않고 대시보드 전용 키로 분리한다 — 대시보드 위젯 문구가 시트 페이지와 항상 동일할 필요는 없고, 향후 개별 수정 시 서로 영향받지 않게 하기 위함(보수적 선택).

## 구현 단계

1. `dashboard/page.tsx`에서 `useSeats()` 훅 호출 추가(`use-observability.ts`에 이미 정의된 것 그대로 import). 로딩/에러는 기존 `data`/`error` 패턴과 동일하게 처리(기존 `isFeatureDisabled` 404 폴백 로직 재사용).
2. `SeatBalanceGauges` 컴포넌트 작성: `SeatObservabilityEntry[]`를 받아 계정별로 5h/7d window의 `pct`를 recharts `RadialBarChart`로 렌더. 각 계정 블록에 리셋 카운트다운(`resets_at` 기준 남은 시간, 클라이언트 계산)과 소진 예측 배지(`projected_exhaustion_at` && `!will_last_to_reset`일 때만 노출)를 붙인다. scoped(모델별) window는 별도 서브 그룹으로 표시.
3. `SeatRankingTable` 컴포넌트 작성: `SeatObservabilityEntry[]`를 `usage_24h_input_tokens + usage_24h_output_tokens` 내림차순 정렬 후 순위·계정(email)·24h 소비·잔량(7d %) 4컬럼 테이블 렌더. "최근 사용일" 컬럼은 넣지 않는다(가정 참고).
4. 두 컴포넌트를 각각 `BentoCard`로 감싸 `BentoGrid`에 추가하고, 두 카드 모두 `href="/observability/seats"`로 설정.
5. 빈 상태(`seatsData.items.length === 0`): 기존 카드들의 `{t("empty")}` 패턴과 동일하게 `<p className="mt-4 text-xs text-[var(--text-muted)]">{t("...")}</p>` 렌더.
6. 다크모드/반응형: 기존 카드와 동일하게 CSS 변수(`var(--text-*)`, `var(--border-subtle)`, `var(--bg-hover)`) + Tailwind `dark:` 없이(변수 기반이라 자동 대응) 그대로 사용. 반응형은 `BentoGrid`의 기존 그리드 컬럼 규칙에 맡기고 위젯 내부에서 별도 breakpoint 로직 추가하지 않는다.
7. `ko.json`/`en.json`에 필요한 키 추가(제목, empty, 컬럼 헤더, 소진 배지 라벨, 카운트다운 단위 등).
8. `__tests__/dashboard-seat-widgets.test.tsx`: (a) `items: []`일 때 empty 텍스트 렌더 확인, (b) 24h 소비 합산 기준 정렬 순서 확인(고정 mock 데이터로 원장 대조 검증에 준하는 단위 테스트).

## 준수할 컨벤션

- 파일명 kebab-case, named export(page.tsx는 default 유지), 신규 인터페이스는 `{ComponentName}Props` 네이밍.
- API 호출은 `lib/api-client.ts`의 `observability.getSeats`만 사용(직접 fetch 금지) — 이미 `useSeats` 훅으로 래핑되어 있으므로 훅만 호출.
- TanStack Query로만 서버 데이터 취급(Zustand에 저장 금지) — `useSeats`가 이미 `useQuery` 기반.
- `any` 금지, 인라인 스타일 금지(단 게이지 퍼센트 너비 등 동적 값은 기존 도넛 위젯처럼 `style={{...}}` 예외 허용 — 기존 코드 관례).
- shadcn/ui 원본 컴포넌트(`components/ui/*`) 직접 수정 금지 — `bento.tsx`는 이미 `href`/`onClick`을 지원하므로 수정 불필요.
- 다크모드는 CSS 변수(`var(--*)`) 우선 사용(CE-403에서 `--chart-danger/warning/info` 도입 완료, 재사용).
- i18n은 `next-intl`의 `useTranslations("observability.dashboard")` 패턴 그대로 따름.

## 도메인 제약 (Domain Constraints)

- **정합성 규칙**: "최근 사용일" 등 시스템에 존재하지 않는 시각 데이터를 근사치(예: 스냅샷 조회 시각)로 대체해 노출하지 않는다 — 사용자에게 잘못된 의미를 전달하는 컬럼/배지는 차라리 생략한다(CE-405 명시 지침, D5 seat_profiles 전까지 계속 유효할 프로젝트 수준 원칙).
