## 목표
QA 판정이 통과가 아닌 런(실패/판정불가/리뷰 실행 불능)에서 `handle_task_failure` 호출 직전에 `.ralph/REVIEW.md`·`.ralph/review.stream.jsonl`을 `logs/qa_failed/<ISSUE_KEY>_<ts>/`로 승격(cp, 재생성 없음)하여 QA 실패 사유를 보존한다.

## 가정 (Assumptions)
- 새 토글은 도입하지 않는다 — 기존 QA 판정/재시도 로직을 변경하지 않고 실패 직전에 파일을 복사만 추가하는 순수 부가 동작이므로, `FLOWOPS_GOVERNANCE_PROMOTE`처럼 별도 마스터 토글 없이 항상 동작해도 회귀 위험이 없다(가장 보수적 대안인 "토글 신설"보다, 기존 파괴적 동작 직전에 읽기 전용 백업을 추가하는 쪽이 실패 모드가 적다).
- 타임스탬프 형식은 기존 관례(`archived_at=$(date '+%Y-%m-%d %H:%M:%S')`, 라인 1638)와 달리 디렉토리명에 쓰이므로 콜론 등 파일시스템 비호환 문자를 피해 `%Y%m%d_%H%M%S`를 사용한다(디렉토리명 용도이므로 가장 안전한 포맷 선택).
- 승격 대상은 두 실패 호출부(라인 1276, 1289) 모두 — 판정 실패(rc≠0)와 리뷰 실행 불능 둘 다 "QA 실패 사유 유실" 문제의 대상이므로 동일 처리.
- `.ralph/review.stream.jsonl`이 없는 경우(리뷰 실행 불능 경로, 라인 1289)도 있으므로 각 파일 존재 여부를 개별적으로 `[ -f ]` 가드한다(기존 라인 1629 관례와 동일).

## 대상 파일
- `scripts/auto_dev_pipeline.sh` — 라인 1274~1282(QA 판정 실패/판정불가 분기)과 라인 1286~1293(QA 리뷰 실행 불능 분기), 각각 `handle_task_failure` 호출 **직전**에 승격 블록 삽입. 기존 `logs/governance/${ISSUE_KEY}` 승격 블록(라인 1616~1642)의 코드 스타일(`mkdir -p` + `[ -f ] && cp` + manifest)을 재사용.

## 구현 단계
1. `handle_task_failure` 호출부 두 곳(라인 1276 직전, 라인 1289 직전) 앞에 공통 승격 로직을 삽입한다:
   ```bash
   if [ -f .ralph/REVIEW.md ] || [ -f .ralph/review.stream.jsonl ]; then
     QA_FAIL_DIR="logs/qa_failed/${ISSUE_KEY}_$(date '+%Y%m%d_%H%M%S')"
     mkdir -p "$QA_FAIL_DIR"
     [ -f .ralph/REVIEW.md ] && cp .ralph/REVIEW.md "$QA_FAIL_DIR/REVIEW.md"
     [ -f .ralph/review.stream.jsonl ] && cp .ralph/review.stream.jsonl "$QA_FAIL_DIR/review.stream.jsonl"
     log "QA 실패 산출물 보존: $QA_FAIL_DIR"
   fi
   ```
   - 판정 실패 분기(1276 직전)에서는 `$VERDICT_OUT`을, 리뷰 실행 불능 분기(1289 직전)에서는 실패 사유 문자열을 `manifest.txt`에 함께 남길지는 선택 사항(로그 라인만으로도 수용 기준 충족 가능 — 과설계 방지를 위해 manifest는 생략하고 `log`만 남긴다).
   - 두 곳에서 동일한 블록을 반복 삽입한다(2회뿐이므로 함수로 추출하지 않음 — YAGNI, 기존 라인 1616~1642 승격 블록도 별도 함수화되어 있지 않음).
2. 라인 583~586의 CE-399 시작 시 무조건 삭제(`rm -f .ralph/TASK.md .ralph/REVIEW.md .ralph/review.stream.jsonl`)는 **변경하지 않는다** — 승격이 이 삭제보다 먼저(이전 이터레이션의 실패 처리 시점) 일어나므로, 다음 런 시작 시엔 이미 옮겨진 뒤라 삭제 대상이 없거나 있어도 그대로 삭제되어 무회귀.
3. 성공 경로(라인 1616~1642, 1644~1648)는 손대지 않는다.

## 테스트
- `scripts/tests/test_workspace_delivery.sh` 등 기존 셸 테스트 스위트를 그대로 실행해 green 확인(수정 파일이 `auto_dev_pipeline.sh` 단독이므로 기존 테스트 전부 대상).
- 신규 테스트 케이스(가능하면 기존 테스트 파일에 케이스 추가, 새 테스트 파일 신설은 지양):
  - QA 판정 실패(rc=1) 시뮬레이션 → `logs/qa_failed/<KEY>_*/REVIEW.md` 생성 확인.
  - QA 리뷰 실행 불능(REVIEW.md 미생성) 시뮬레이션 → REVIEW.md가 없으므로 `review.stream.jsonl`만(또는 둘 다 없으면 디렉토리 자체 미생성) 확인.
  - QA 판정 통과(성공 런) 시뮬레이션 → `logs/qa_failed/`에 아무 것도 생성되지 않음(회귀 없음) 확인.
  - 승격 후 다음 이터레이션 시작 시 `.ralph/REVIEW.md`가 존재하지 않음(CE-399 무회귀) 확인.

## 준수할 컨벤션
- 커밋 메시지: `[api] 작업 내용` 형식, 한국어.
- "재생성 없이 승격만"(기존 `FLOWOPS_GOVERNANCE_PROMOTE` 패턴, 라인 1616~1642)과 동일한 방식(`cp`, `mkdir -p`) 재사용 — 새로운 아카이브 메커니즘을 창작하지 않는다.
- 최소 수정안: 파일 1개(`scripts/auto_dev_pipeline.sh`) 내 국소 삽입, 기존 로직·토글 체계 변경 없음(T2~T3 수준).
