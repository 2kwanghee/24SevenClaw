## 목표
대시보드 홈(`clickeye-web/src/app/(dashboard)/dashboard/page.tsx`)에 CE-411 API(`GET /observability/delivery-board`) 데이터를 쓰는 전폭 딜리버리 진행 보드(스윔레인·8단계 카드·트래픽 애니메이션)를 최상단에 추가하고, 기존 위젯 4종을 보드 아래 2열 컴팩트 레이아웃으로 재배치한다.

## 가정 (Assumptions)
- **8단계 매핑 불일치**: CE-411 스키마(`DeliveryBoardStages`)는 프로젝트 레벨 체크포인트로 `received_at/refined_at/accepted_at/issued_at` 4개만 제공하고, 요청된 8컬럼(접수→정제→승인→발급→구현→QA→게이트→완료)은 티켓 레벨 `stage: str`/`stage_history[].stage`(자유 문자열, enum 미정)로 구성해야 한다. → `STAGE_COLUMNS = [received, refined, accepted, issued, implementing, qa, gated, done]` 8키 상수를 프론트에 정의하고, 백엔드가 내려주는 `stage` 문자열을 이 키에 매핑하는 딕셔너리를 둔다. 매핑되지 않는 미지 값은 크래시 대신 마지막 컬럼(완료) 앞 "미분류" 처리 없이 **가장 보수적으로 직전 알려진 컬럼에 그대로 유지**하고 콘솔 경고만 남긴다(백엔드 계약 변경은 금지범위이므로 프론트 단독 대응).
- **레인 위 체크 도트(통과 단계)** 는 프로젝트 레벨 `DeliveryBoardStages` 4개 타임스탬프만으로 표시(접수·정제·승인·발급 4개 도트), 티켓 카드가 위치하는 8컬럼 축과는 별개 트랙으로 렌더한다 — API가 프로젝트 단위 완료 시각을 8개 다 주지 않으므로 무리하게 추정하지 않는다.
- 애니메이션 대상 "직전 완료 단계"는 `ticket.stage_history` 배열의 마지막-1 항목으로 정의(배열 비어있으면 애니메이션 생략, 정적 렌더만).
- `active=true`인 티켓이 하나도 없으면 애니메이션 레이어 자체를 마운트하지 않는다(성능/단순성).
- 프론트 전용 wrapper가 없으므로 신규 API 클라이언트 함수·훅을 추가한다(계약은 이미 `clickeye-contracts/generated`에 존재 — 신규 스키마 작업 아님, 금지범위의 "백엔드" 소관 아님).
- outcome이 `failed` 또는 intake_status가 `Backlog`인 티켓은 danger 톤(`--chart-danger`) 고정, 그 외는 8단계 중 현재 위치 컬럼에 대응하는 `--chart-*`/`--accent` 톤 사용(신규 색상 변수 추가 없이 기존 토큰 재사용).

## 구현 단계
1. `use-observability.ts`에 `useDeliveryBoard()` 추가, `api-client.ts`에 대응 함수 추가(자동생성 SDK의 `sdk.gen.ts:4267` 호출 래핑, 직접 fetch 금지 컨벤션 준수)
2. `STAGE_COLUMNS`(8키) 상수·라벨 i18n 키·색상 매핑 유틸을 `delivery-board.tsx`(또는 인접 `delivery-board-constants.ts`)에 정의
3. `delivery-board.tsx`: 헤더(8컬럼, 가로 스크롤 컨테이너 + `sticky` 헤더), 데이터 없으면 empty 문구, `isLoading`이면 `DeliveryBoardSkeleton`, 에러(404)면 기존 `featureDisabled` 패턴 재사용
4. `delivery-board-lane.tsx`: 프로젝트명 + intake_status 뱃지, 프로젝트 레벨 4단계 체크 도트+실선, 해당 레인의 티켓들을 `stage` 매핑 결과 컬럼에 배치
5. `delivery-board-ticket-card.tsx`: 키·제목 요약(truncate)·`duration_s` 사람이 읽는 시간 포맷, outcome=failed/Backlog danger 톤 분기
6. `delivery-board-flow-animation.tsx`: SVG path(직전 컬럼→현재 컬럼) + `circle` 파티클, CSS `@keyframes`로 `stroke-dashoffset` 이동. `window.matchMedia('(prefers-reduced-motion: reduce)')`로 정적 펄스(opacity keyframe) 대체
7. 반응형: `md:` 이상 가로 스윔레인, 모바일은 각 프로젝트를 세로 스택 카드 리스트로 전환(Tailwind만, 신규 브레이크포인트 없음)
8. `page.tsx`에 `<DeliveryBoard />` 삽입 위치 조정 + 기존 4위젯 그리드 클래스 변경(로직 코드는 이동만, 삭제 없음)
9. 다크모드는 기존 `dark:`/CSS 변수 패턴만 사용, 별도 분기 컴포넌트 만들지 않음
10. i18n: `ko/en` 메시지 키 추가 후 `useTranslations("observability.dashboard")`로 소비

- TanStack Query만 사용(Zustand 금지), API 호출은 자동생성 클라이언트 경유(직접 fetch 금지) — `clickeye-web/CLAUDE.md`

## 도메인 제약 (Domain Constraints)
- **정합성 규칙**: 티켓의 `stage`/`stage_history`는 백엔드가 자유 문자열로 내려주며 8단계 고정 enum이 계약상 보장되지 않는다 — 프론트는 매핑 실패를 자체 흡수(경고 로그)해야 하며, 미지 stage 값으로 인한 렌더 크래시가 없어야 한다는 것이 이 도메인(딜리버리 진행 보드)의 지속적 불변식이다.
