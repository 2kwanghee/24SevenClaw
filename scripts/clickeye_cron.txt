# ClickEye crontab 정본 (CE-338)
# ─────────────────────────────────────────────────────────────────────────────
# 이 파일은 "정본"일 뿐 자동 등록되지 않는다. 아래 절차로 사용자가 등록한다.
#
# [등록 전 필수] 죽은 옛 항목 제거
#   기존 등록본은 존재하지 않는 경로 /mnt/c/workspace/24SevenClaw 를 가리켜
#   전 항목이 무효였다. 먼저 경로를 검증하고, 옛 경로 항목을 제거해야 한다.
#     crontab -l                                         # 현재 등록 확인
#     crontab -l | grep -oP "cd \K[^ &]+" | sort -u      # 모든 cron 의 cd 대상 확인
#       → /mnt/c/workspace/ClickEye 만 남아야 정상.
#         /mnt/c/workspace/24SevenClaw 가 섞여 있으면 `crontab -e` 로 그 줄 삭제.
#
# [등록 전 필수] PATH 검증
#   cron 은 최소 PATH(/usr/bin:/bin)로 실행되므로 아래 PATH= 지시가 로컬 설치
#   위치와 일치해야 한다. 등록 전 반드시 실측하고 아래 PATH= 값과 대조할 것:
#     command -v claude ngrok python3 uv npm
#   실측(2026-07-30): claude=/home/lkh/.local/bin, uv=/home/lkh/.local/bin,
#     ngrok=/home/lkh/bin, python3=/usr/bin, npm=/usr/bin.
#   설치 위치가 다르면 아래 PATH= 를 그 위치에 맞게 수정한 뒤 등록한다.
#
# [등록]
#     (crontab -l 2>/dev/null; cat /mnt/c/workspace/ClickEye/scripts/clickeye_cron.txt) | crontab -
#     crontab -l                                         # 등록 결과 확인
#   (중복 등록 방지를 위해 등록 전 옛 항목을 반드시 제거할 것)
#
# [주의] webhook_server 는 더 이상 호스트에서 watchdog 로 띄우지 않는다.
#   수신부는 compose 서비스(webhook, 컨테이너, WEBHOOK_ENQUEUE_ONLY=true)로 대체됐고,
#   호스트는 큐를 소비하는 워커(webhook_worker.py)만 watchdog 로 유지한다.
# ─────────────────────────────────────────────────────────────────────────────

# cron 실행 환경. PATH 미지정 시 claude/ngrok/uv 가 not found 로 조용히 실패한다.
# (실측 위치는 위 "[등록 전 필수] PATH 검증" 참조 — 변경 시 이 줄도 함께 갱신.)
SHELL=/bin/bash
PATH=/home/lkh/.local/bin:/home/lkh/bin:/usr/local/bin:/usr/bin:/bin

# ── 파이프라인 실행(호스트) ──────────────────────────────────────────────────
# 업무시간 폴링: 평일 09~18시 5분마다 1회 실행(잔여 Queued 이슈 처리).
# [필수] 아래 디스패처를 켜면 이 단일 러너와 전용 러너가 같은 `[수주:] ` 티켓을 다툰다.
#   디스패처를 켜기 **전에** 이 줄에 `WATCHER_EXCLUDE_PREFIXES` 를 붙여 전용 러너가 맡은
#   프로젝트를 제외해야 한다. 구분자는 **탭**이다(접두사가 공백을 포함하므로 공백 구분 불가).
#   auto_dev_pipeline.sh 는 `--exclude-prefix` 인자를 넘기지 않지만(본체 무수정), watcher 가
#   이 env 를 직접 읽으므로 cron 라인만 고치면 된다. 예(전용 러너 2개를 제외):
#     */5 9-18 * * 1-5 cd /mnt/c/workspace/ClickEye && WATCHER_EXCLUDE_PREFIXES="$(printf '[수주:aaa11111] \t[수주:bbb22222] ')" bash scripts/auto_dev_pipeline.sh --once >> logs/pipeline-cron.log 2>&1
#   설정 후 검증: python3 scripts/linear_watcher.py --dry-run 출력에 제외 대상이 없어야 한다.
*/5 9-18 * * 1-5 cd /mnt/c/workspace/ClickEye && bash scripts/auto_dev_pipeline.sh --once >> logs/pipeline-cron.log 2>&1
# 러너 디스패처(P5/CE-346): 워크스페이스별 전용 러너를 clone 안에서 스폰/감시/회수.
#   FLOWOPS_RUNNER_DISPATCH 미설정이면 SKIP 후 exit 0 이므로 등록해도 무해하다(회귀 0).
#   틱 중첩은 flock(.ralph/dispatch/.dispatch_lock)이 막고, 동시 러너 수는 active 시트 수로 캡.
*/5 9-18 * * 1-5 cd /mnt/c/workspace/ClickEye && bash scripts/runner_dispatcher.sh >> logs/dispatcher.log 2>&1
# 야간 배치: 매일 자정, 최대 50반복으로 밀린 작업 소진.
0 0 * * * cd /mnt/c/workspace/ClickEye && bash scripts/auto_dev_pipeline.sh --max-iterations 50 >> logs/pipeline-night.log 2>&1
# confirmer: 평일 정오, Confirm 상태 이슈 확정 처리.
0 12 * * 1-5 cd /mnt/c/workspace/ClickEye && python3 scripts/linear_confirmer.py >> logs/confirmer.log 2>&1

# ── 인테이크 3배치(로컬 LLM 실행 — refine→issue→verify 체인) ──────────────────
# 서로 겹치지 않게 1시간 간격으로 배치한다. 근거:
#  · 야간 배치(0 0)의 부하가 가라앉은 뒤 02시부터 시작(폴링 창 09~18시와도 무충돌).
#  · issue 는 refine 이 만든 "정제 스펙"을 소비하므로 refine 이 먼저 끝나야 한다.
#  · verify 는 issue 가 발급한 티켓의 완주를 검증하므로 issue 뒤에 온다.
#  · 각 배치는 MAX_ITEMS 하드캡 + CLAUDE_TIMEOUT(refine 300s/issue 600s)로 상한이
#    있어 1시간 간격이면 서로의 실행 창을 침범하지 않는다.
# (모두 opt-in 토글. 토글 미설정 시 스크립트가 [SKIP] 후 exit 0 — 회귀 0.)
# 정제: 02시 — 인테이크 원문 → 구현 스펙(FLOWOPS_INTAKE_REFINE).
0 2 * * * cd /mnt/c/workspace/ClickEye && FLOWOPS_INTAKE_REFINE=true bash scripts/intake_refine.sh >> logs/intake-refine.log 2>&1
# 발급: 03시 — 정제 스펙 → Linear 티켓 전량 발급(FLOWOPS_INTAKE_ISSUE).
#   FLOWOPS_INTAKE_AUTO_ACCEPT 는 서버(clickeye-api)가 강제하는 토글이다. 여기 인라인
#   지정은 서버에 그 토글이 켜져 있을 때만 pending_review 기계수락이 진행됨을 뜻한다.
0 3 * * * cd /mnt/c/workspace/ClickEye && FLOWOPS_INTAKE_ISSUE=true FLOWOPS_INTAKE_AUTO_ACCEPT=true bash scripts/intake_issue.sh >> logs/intake-issue.log 2>&1
# 검증: 04시 — 발급 티켓 완주 → 정합성 게이트 → verified 확정(FLOWOPS_DELIVERY_VERIFY).
#   게이트 명령 소스: VERIFY_GATES_FILE 미지정 시 저장소 루트 .clickeye-gates.txt 자동 탐지.
#   둘 다 없으면 verifier 가 exit 5(검증 불가)로 관측만 하고 verified 전이는 하지 않는다.
0 4 * * * cd /mnt/c/workspace/ClickEye && FLOWOPS_DELIVERY_VERIFY=true bash scripts/delivery_verify.sh >> logs/delivery-verify.log 2>&1

# ── watchdog(10분마다 살아있는지 확인, 죽으면 재기동) ─────────────────────────
# 웹훅 실행 워커(호스트 상시 루프): 큐 소비 담당. 기존 webhook_server watchdog 을 대체.
# 패턴은 문자클래스 형태([w]…)로 둔다. cron 이 `/bin/sh -c` 로 실행하는 이 줄 자신의
# cmdline 에 pgrep 패턴이 그대로 들어가므로, "webhook_worker.py" 로 쓰면 pgrep 이 자기
# 자신에 매칭되어 워커가 죽어도 재기동 분기가 절대 실행되지 않는다(실측 확인).
*/10 * * * * pgrep -f "[w]ebhook_worker.py" > /dev/null || (cd /mnt/c/workspace/ClickEye && nohup python3 scripts/webhook_worker.py >> logs/webhook-worker.log 2>&1 &)
# ngrok 터널(Linear → 호스트:9876 → compose webhook 컨테이너).
*/10 * * * * pgrep -f "[n]grok http 9876" > /dev/null || (cd /mnt/c/workspace/ClickEye && nohup ngrok http 9876 --log=logs/ngrok.log --log-format=logfmt >> /dev/null 2>&1 &)
