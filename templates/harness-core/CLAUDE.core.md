# 구현 코어 규약 (Harness Tier 0 — 불변)

이 문서는 프로젝트 종류와 무관하게 모든 구현 작업에 적용되는 공통 규약이다.
자동/대화형 하네스가 워크스페이스를 조달할 때 이 파일을 그대로 복사한다.
스택별 명령(test/lint/build)은 함께 생성되는 `CLAUDE.stack.md`를 참조하라.

## 코드 작성 규칙
1. **기존 패턴 준수**: 새 코드는 주변 코드의 스타일·명명·구조·의존성을 따른다.
   새 라이브러리를 도입하기 전에 매니페스트(package.json / pyproject.toml / go.mod 등)에
   이미 있는지 확인한다.
2. **수정 전 읽기**: 파일을 수정하기 전에 반드시 먼저 읽는다.
3. **절대 경로 사용**: 파일 참조는 절대 경로로 한다.
4. **최소 변경**: 요청된 범위만 수정한다. 무관한 리팩터링·포맷 변경을 섞지 않는다.

## 테스트
- 새 기능·버그 수정에는 반드시 테스트를 동반한다.
- 변경 영역의 테스트 커버리지 ≥70%를 목표로 한다.
- 구현 완료 전 스택의 lint·타입체크·테스트 명령을 통과시킨다(`CLAUDE.stack.md` 참조).

## 커밋·주석
- 커밋 메시지와 코드 주석은 한국어로 작성한다.
- 커밋 형식: `[모듈] 작업 내용` (예: `[api] 인증 엔드포인트 구현`).
- 주석은 코드가 스스로 드러내지 못하는 제약·의도만 남긴다. 무엇을 했는지 나열하지 않는다.

## 금지 사항
- 명시적 요청 없이 자동 커밋하지 않는다.
- 검증 없이 작업 완료를 선언하지 않는다. lint·테스트 실패는 실패로 보고한다.
- 안전 규칙(권한·시크릿 취급)을 우회하지 않는다.
- 이 코어 규약 파일을 임의로 수정하지 않는다(Tier 0 불변).
